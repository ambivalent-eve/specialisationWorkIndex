Information Design

Prototype 1

The first prototype. Here, I wanted to emulate an audio player for the purposes of experimenting with player controls. I had the three most common buttons presented, such as the play, skip and shuffle button and presented them to the user for use in hopes that the buttons presented would be intuitive. The chosen technique here was loadData(IndexValue) where I emulated the randomness of a song through index values. When clicking the shuffle button, the code would select a random index number and then play a song associated to that index. Whilst this worked for that singular purpose, it doesn't actually shuffle the playlist and instead just plays a random song.

Prototype 3

Here I decided to try adding clear instructions to the user so that they could try playing with the new play interactions. I added text instructions such as "press space to play" and whatnot whilst focusing on changing the eventListener to use keydown instead of click. I changed the play to work with space, skip to work with enter and r to work with shuffle. The visual changes weren't very much but I wanted to experiment and learn with how I could use the keys as part of the interactive experience. I was initially going to use tab as shuffle but it would conflict with the browser shortcuts so I avoided it.

Prototype 6

In this I focused on the sliders as information design. I wanted the users to be able to intuitively know that they could adjust the sliders in order to change the volume/pitch of the song. The only indicators I gave were that the sliders belonged to volume and pitch. Feedback

Prototype 2

For this prototype, I wanted the users to actually see when their queue actually shuffles, otherwise it would've felt like the shuffle button was there for decoration. First, I improved on the shuffle code by changing to the Fisher Yates Shuffle through the help of the agent in Visual Studio Code. With Math.random, I was able to shuffle the entire playlist and customised it so that it only shuffled the rest of the queue and not the current song. Afterwards, I had help creating a code that would actually demonstrate the queue randomising. I also made it so that when your mouse hovers over the buttons, it changes the cursor to infer interactivity.

Prototype 4

I focused on implementing a bar the user can click to change the time placement of the song. By clicking on it, the timestamp will change to reflect the new position. In this prototype I used the click input with eventListener a lot in order to make the users interactions have responsive feedbacks. When the user clicks on a button that adds rain or slows the song down, the button changes colour to green to reflect that the button is activated.

Prototype 5

I decided to radically change the format of the website to try and emulate a soundboard. I gathered a list of different sound effects from copyright-free websites and assigned each of them to a buttonid that would activate on click. When the user clicks on the button, the code sends a feedback back to the user with the sound that should be played with audio.play(). When clicking on the buttons, they change colour for a little bit every time they're clicked on to also give the visual feedback of being activated. Same for when they're hovered over.

Conclusion

Though none of the prototypes are definitive, I found that exploring each of them with a different purpose in mind helped make for a more solidified idea for the final website. I think what the ultimate idea would be is a way to somehow combine most of these prototypes together. A soundboard where you could play sound effects or perhaps add sounds to queue, a functional audio player, a way to customise the song with different pitches, additional sounds to play in the background such as rain and even functional keyboard controls.
